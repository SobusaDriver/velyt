# velyt landing page

Marketing site + deep-link verification files for velyt.

## Where it lives

| | |
| --- | --- |
| Live site | https://sobusadriver.github.io/velyt/ |
| Deploy source (public repo) | https://github.com/SobusaDriver/velyt |
| This folder | `velyt-app/site/` (mirror of that repo) |

`velyt-app` is private and GitHub Pages cannot serve it on the free plan, so
`SobusaDriver/velyt` is a public mirror of this folder. The live site is built
from the root of that repo's `main` branch.

## How to deploy

Generated assets and pages come from app code, so build them first:

```bash
pnpm site:build   # writes site/assets/financing.js + site/assets/analytics.js
```

Then copy `site/` into the public mirror repo and push:

1. Make the change in `SobusaDriver/velyt`, or make it here and copy the files
   over.
2. Commit and push to `main`:

   ```bash
   git clone https://github.com/SobusaDriver/velyt.git
   cd velyt
   # edit index.html / assets
   git commit -am "..." && git push origin main
   ```

3. The repo's `Deploy site to GitHub Pages` workflow runs on every push to
   `main` (and on manual dispatch), uploads the repo root and deploys with
   `actions/deploy-pages@v4` in about 20 seconds. Check it with:

   ```bash
   gh run list -R SobusaDriver/velyt --limit 1
   ```

4. Verify the live page:

   ```bash
   curl -sI https://sobusadriver.github.io/velyt/
   ```

GitHub Pages must stay configured as **Settings → Pages → Source: GitHub
Actions** in that repo.

Do not re-add a Pages workflow here: Pages is not enabled for `velyt-app`, so
`actions/deploy-pages` fails with `Not Found`. The previous `deploy-site.yml` in
this repo was removed for that reason.

## Web onboarding

`/onboarding/` asks the same nine profiling questions as the app (including the
vehicle age and brand-style steps) (labels come from
`src/i18n/es.ts`), then calls the **same Postgres function the app uses**
(`match_vehicles`) through Supabase's REST API with the publishable key, and shows
the top **12 matches** with the match score and its reasons. Each card also shows a
fair-price range computed by the app's own estimator (`fairprice.js`) from Revista
Motor values (`vehicle_prices`, public) plus the catalog range. It is deliberately limited: no fair price, peritaje, alerts or saved
vehicles. Every card links to `/search/vehicle/<id>` (universal link into the app)
and the page carries an App Store CTA tagged `ct=web-onboarding`.

Answers are stored in `localStorage["velyt:onboarding"]`, so a returning visitor
skips the intro. No account, no email, nothing sent to a server.

## Copy claims

The page never names a price source. It says **"referencias de mercado"** and
**"27.7k+ precios de referencia"**, and always with a `+` so a growing database
never makes the claim wrong. The exact provenance stays here:

| What the page says | Where it comes from |
|---|---|
| **3.300+ vehículos**, 154 marcas | `select count(*) from vehicles` → 3.303 (1.801 modelos) at the time of writing |
| **9 preguntas** | `PROFILING_STEP_IDS` in `src/domain/profilingGate.ts` (9 questions + confirm) |
| **9+ portales** | the 9 scrapers in `src/services/listings/index.ts` (autocosmos, autoland, bellpi, wcar, carroya, delaespriellamotors, triplo, vendetunave, loscoches) |
| **12.8k+ referencias de mercado** | `select count(*) from vehicle_prices` → 12.848 rows (9.276 Revista Motor + 3.572 Fasecolda, one per model-year after de-duplication) |

Three rules that were easy to get wrong:

- Marketplace listings are **not** valuation inputs. The fair price blends
  Revista Motor, Fasecolda and the catalog — see `docs/fair-price-estimator.md`.
  The 9+ portals are where the cars come from, not where the price comes from.
- The peritaje reports accident data only where a public source records it (the
  national RUNT/SIMIT data does not include a national claims database), so the
  copy says "donde la fuente pública los registra".
- Source names (Revista Motor, Fasecolda) stay in the docs and in the code. The
  UI shows "Guía oficial" / "Guía de mercado" and "Referencia de mercado".

Change these numbers only in `index.html` (`#src1`, `#src2`, the three gauges, and
the `es`/`en` translation maps) and keep this table in sync.

## Analytics and install attribution

`assets/analytics.js` loads posthog-js and captures a `cta_click` for any element
with `data-cta`. App Store links carry `?ct=web-landing` or `?ct=web-calculadora`.

Installs are only attributed by Apple when the link also has the provider token:
`https://apps.apple.com/co/app/velyt/id6778179192?pt=<provider-token>&ct=<slug>`.
Add `pt` in `index.html` (two places) and `calculadora/index.html` once it is
known in App Store Connect.
